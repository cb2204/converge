Priority scale

P0 the thesis is at risk — the project is currently contradicting its own claims · P1 the roadmap's named commitments · P2 compounding value, scheduled after the commitments · P3 breadth that can wait for pull.

Effort tiers — the six-tier scale

The same scale the gate enforces on Task-Specs: XS ≤ 1 write path · S ≤ 2 · M ≤ 3 · L ≤ 5, one coherent goal · XL / XXL are nodes — never runnable, they dispatch children.

Proves — proposed gates

Each item ends in the check that will decide it. Existing tokens (DOCTOR_HOST_TESTS=PASS) are the real gates today; proposed tokens (EVAL_GATE=OK) become real when the item's Task-Spec is authored and sealed. A proposal is not a verdict.

Why Epic A outranks everything. Converge's pitch is “done is proven, never claimed” — and as of 2026-08-05 its own proof surface is dark: every CI run since 2026-08-03T20:17Z has failed in 3–13 seconds with no step executed and job logs returning 404 (runner-allocation shape, not a test failure), while the README still says “CI is public and green.” Eight commits of new gate logic sit unverified by the gauntlet. A trust product wearing a red badge under a green claim is the one contradiction the thesis cannot survive — so relighting the floor is the whole of horizon one.

C

The Manager — fleet dispatch across the ready frontier.

HORIZON · NEXT (0.2)ROADMAP · TOP ITEM2 ITEMS · 1 NODEEXIT · N TASKS, N NAMED LANDINGS

The loop is single-task by design today; the Manager decides which task runs, when, in parallel, watching PRs. The design stance is already set — a Git-native world provides most of the orchestration (Actions as scheduler, PR as settlement) — so the Manager schedules around the loop rather than replacing it. Its safety story is inherited, not invented: every child is a normal bounded loop under a sealed spec and the write fence.

05

Backlog → Task-Specs. This document is upstream of Pass 5, on purpose.

This backlog sits at plan altitude — the same altitude as swimlane legs: one responsibility, a proves-line, no eval bodies. Scheduling an item means walking it through the factory's own front half, not around it:

$ cvg lane "fix the doctor-host suite portability" # → FAST $ cvg tasks new fix-doctor-host-portability XS # scaffold — evals FIRST # author the evals from this item's “proves” line, then: $ cvg tasks validate cvg/tasks/T-*.md $ cvg tasks gate --stamp cvg/tasks/T-*.md VERDICT: DELEGATE · TIER=1 $ cvg bind --task cvg/tasks/T-*.md && cvg loop --issue T-… --agent codex TASK_LOOP=SETTLED # the item leaves this page
The exit criterion for this whole document

Every P0 item settled through the loop with its token green, the eval-gate required on main, and the README's status section describing a state that a stranger can re-measure. At that point this backlog regenerates from the board — it stops being a file and becomes a query.

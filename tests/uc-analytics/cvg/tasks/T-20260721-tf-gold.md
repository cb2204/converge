# Transform — gold revenue + transitive-join slices

## Goal
Model gold on silver: revenue = SUM of captured payment amounts (ADR-0004, never order totals or 'paid'); revenue-by-product routes the transitive join payments->orders->products (ADR-0006, no payments.product_id); gold matches the answer-key oracle.

## Success Criteria
```bash
# Every check asserts DATABASE STATE or EXECUTES the artifact — never file
# shape. A stub file cannot create a table, populate a column, or revoke a
# privilege. `make up` must be running (uc-analytics-postgres).
PG="docker exec uc-analytics-postgres psql -U postgres -d ecommerce -tAc"

# B-1: gold revenue counts CAPTURED orders, not paid ones. Reconciled against
# an oracle computed independently from the source tables.
eval_1() {
  test -f cvg/transform/models/gold/revenue.sql || return 1
  gold=$($PG "select coalesce(round(sum(revenue)::numeric,2), -1) from gold.revenue" 2>/dev/null)
  oracle=$($PG "select coalesce(round(sum(o.total_amount)::numeric,2), -2) from orders o" 2>/dev/null)
  [ -n "$gold" ] && [ "$gold" = "$oracle" ]
}

# B-2: no fan-out. Joining payments must not multiply product rows — the gold
# grain must equal the number of distinct products.
eval_2() {
  test -f cvg/transform/models/gold/revenue_by_product.sql || return 1
  rows=$($PG "select count(*) from gold.revenue_by_product" 2>/dev/null)
  prods=$($PG "select count(distinct product_id) from products" 2>/dev/null)
  [ "${rows:-0}" -gt 0 ] || return 1
  [ "${rows:-0}" -eq "${prods:-1}" ]
}

# B-3: the oracle test exists AND passes against the warehouse.
eval_3() {
  test -f cvg/transform/tests/oracle_revenue.sql || return 1
  mismatch=$($PG "select count(*) from gold.revenue g
                  where g.revenue is null or g.revenue < 0" 2>/dev/null)
  [ "${mismatch:-1}" -eq 0 ]
}
```

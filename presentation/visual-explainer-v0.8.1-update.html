02 · v0.8.1 behavior

What the new baseline asks every visual explanation to do

Version 0.8.1 is less about decoration and more about choosing the right representation, preserving source detail, and proving the page works in a real browser.

1

Route by information shape

Use Mermaid for topology, semantic tables for matrices, CSS cards for text-heavy architecture, and a hybrid overview-plus-detail pattern when a system has more than about fifteen elements.

2

Preserve the evidence

Tables keep their rows and columns; technical recaps verify paths, commands, behavior, and history against the source instead of polishing stale narrative.

3

Make long pages navigable

Pages with four or more major sections use responsive navigation: a sticky sidebar on desktop and a horizontally scrolling section bar on mobile.

4

Engineer overflow away

Grid and flex children use min-width: 0; long identifiers wrap; wide tables scroll inside labeled regions; diagrams receive bounded containers.

5

Verify before handoff

Open the result in a browser, check desktop and mobile layouts, inspect console errors and horizontal overflow, and confirm interactive controls work.

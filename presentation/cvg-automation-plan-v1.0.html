cvg — Automating Converge

the CLI · the fleet · the board  ·  plan v1.0  ·  2026-07-16  ·  field-checked against Exa + Firecrawl + Tavily

Converge already compiles a fuzzy brief into HMAC-sealed, self-verifying Task-Specs. This plan wraps the method in one multi-harness CLI — cvg — that frames each pass, dispatches it to any engine, and gates the output. Humans stand at exactly two judgment gates; everything after is machine-gated, graph-scheduled, and verified three times before accepted: true.

02 Field scan — what July 2026 changed in the plan

Swept Exa, Firecrawl, and Tavily. Four findings strengthen the plan, one reshapes it, and one is a warning.

Confirmed · the substrate is real

GitHub Agent HQ hit public preview (Feb 2026) — mission control, agent identity, branch controls for agent-created code, Slack/Linear integrations. Agentic Workflows (tech preview, Feb 13 2026): markdown workflow + gh aw compile → lockfile, runs as Actions with sandboxing. Profile C of the Manager targets this instead of hand-rolled YAML.

Confirmed · headless engines are mature

Every engine now has a scriptable surface: codex exec --json --output-schema --attempts N (best-of-N!), claude -p, Copilot SDK (JSON-RPC, TS/Python, permission handlers), Gemini CLI headless, Kimi CLI is fully model-agnostic (any model via config). The cvg engine adapters are ~20 lines each, on official rails.

Confirmed · standards bet paid

A2A passed 150 organizations and landed in major clouds in its first year — task-spec's ts_a2a_state_v1 mapping is the right interop layer. AGENTS.md is in 60k+ repos, v1.1 (frontmatter + nearest-file precedence) still a live proposal — B-14's AGENTS.md-first inversion stays correct, emit v1.1 behind a flag.

Reshapes · routing is a discipline now

RouteLLM-class routers report 40–85% cost cuts; the 2026 consensus is quality-routing on measured traces, not static rules. Conclusion for cvg route: start with pins + rules, but design the seam so _fleet.jsonl receipts (first-pass rate, cost-per-green per engine per task type) become the router's evidence. Route on receipts, not vibes.

Warning · boards are commoditized

Nine-plus OSS orchestrators now ship worktree-isolated parallel agents with kanban UIs (Vibe Kanban, Agent Kanban, Conductor ×3, Railyard, Claude Squad, Emdash…). None have sealed specs, dual gates, gold-sanity, or executor conformance. The moat is gate semantics — never compete on the board alone.

Steal · the compile pattern

Agentic Workflows' "markdown is source, lockfile is binary, both in git" pattern is exactly the pass-card story: SKILL.md is source, cards/*.md are compiled prompts, a lint keeps them in sync (B-10, now with prior art).

03 The one rule — the CLI is the referee, never a player

Passes split into cognitive work (only a model can do it) and mechanical work (deterministic scripts). The CLI owns all of the second and none of the first. It holds zero model credentials — it shells out to engine CLIs the user already has.

# anatomy of every pass command — frame → dispatch → collect → gate $ cvg attack --adversary codex 1 FRAME read sketch/*.plan + tech-spec + ADRs → render the attack card 2 DISPATCH codex exec --json "<card>" # the engine thinks 3 COLLECT objections.json → write FIXED / ACCEPTED into the plans 4 GATE check-consensus-gate.sh → exit 0 or exit 1 # the CLI verdicts
Why this preserves both moats. The eval defines done (optionality moat) and the CLI enforces it identically for every engine (the gate is unmoved when you swap Claude → Codex → Kimi). The Claude Code skills become thin adapters that call cvg — same two-surface pattern DGE proved, but with Converge's far deeper gate semantics underneath. ~60% of the CLI already exists as the 53 shell scripts inside the skills; v0 is a router, not a rewrite.
04 Routing — different tasks to different models, on evidence

Yes — and it's two independent dimensions: the harness (claude / codex / kimi / copilot) and the model inside it (codex -m, Copilot SDK model:, Kimi = any model). The spec's frontmatter already carries the routing inputs; the router adds a decision layer with a logged rationale.

PriorityLayerDecides fromExample
1 · PINSpec author's explicit choiceexecution_backend: / agent: in frontmatterexecution_backend: kimi — honored unconditionally, logged as "pin"
2 · RULESDeterministic policy tableeffort × severity × dominant tech in touches_pathsXS/S cosmetic → cheap tier · M security → frontier + different-engine verifier
3 · RECEIPTSMeasured evidence (B-8)_fleet.jsonl: first-pass rate, cost-per-green, park rate per engine per task type"kimi: 92% first-pass on dbt tasks at ⅓ cost → route dbt S-tasks to kimi"
Every decision is auditable

Each dispatch logs a rationale record — {task, chose: harness+model, source: pin|rule|receipts, why} — to the ledger. Inspectable and overridable, never trusted blindly (the DGE router lesson, kept).

Reliability lever

For severity: financial-critical, the adapter can use codex exec --attempts N (best-of-N) or dispatch two engines and require agreement — spending compute on certainty exactly where blast radius demands it.

05 The graphs — yes, three of them, all derived, none stored

Everything is graph-shaped, but there is no graph.json. Truth lives in tasks/*.md frontmatter + the tracker + git; the graphs are recomputed on every read. Delete nothing, sync nothing, drift nothing — that is the argument against DGE's stored canonical graph.

① Dependency DAG
  • from depends_on: edges
  • drives dispatch order (topological)
  • DAG-ness = the termination proof
  • cycle check at register time
② Blast-radius graph
  • from touches_paths overlaps
  • drives parallel-safety (serialize collisions)
  • verified post-hoc by accept-task.sh
  • rendered as the overlap map
③ Traceability graph
  • behaviors B-N ↔ evals ↔ tiers
  • drives the tier-2 judge's rubric
  • linted bidirectionally at validate time
  • rendered as the trust ladder wires
The Manager schedules from ① and ②; the verifier reads ③. The board draws all three. One derivation function (shared by cvg status, cvg next, and the board's /state endpoint) means the CLI and the UI can never disagree.

09 Life of one atom — the trust ladder

The Task-Spec carries a field for every rung; nothing new is invented at run time. This ladder is also the board's zoom-2 view — the chain of custody, on screen.

1signed_off + HMACPRE-gate: evals fail for the right reason; bodies sealed; hand-stamps rejected
2routed + dispatchedpin→rules→receipts pick the engine; lock on the issue; isolated worktree; rationale logged
3executed (L2 loop)implement → run evals → RED feeds back; bounded by budget_iterations; park, never spin
4tier 1 · CI re-runclean container re-runs the spec's own evals as a required check — a lying worker cannot merge
5tier 2 · cross-engine judgefresh context, different engine, reads diff vs the Behavior zone; refutes gamed evals; fails closed
6tier 3 · human reviewsummoned by severity × blast radius only — scrutiny scales with consequence, not familiarity
7accepted: trueclean-checkout re-run + blast radius + HMAC intact + gold-sanity (eval fails on baseline) — the only done that counts

11 Build phases — each exits through its own gate

Bottom-up on purpose: automate the machine-checkable end first, keep judgment human until receipts say otherwise. Every phase is cut as Task-Specs — the method builds its own factory.

Phase 0 · now
Validate by hand
greenfield + brownfield

Full descent on both project types, human at every pass. Always --gold-sanity; accumulate _metrics.jsonl; race two sessions once to observe the lock. Exit: both runs converged, metrics baseline exists.

Phase 1
cvg v0 — router + state
B-3 · wraps 53 scripts

One entrypoint over the existing scripts; cvg status / next --json derived from artifacts. Exit: deleting a gate artifact flips its pass red.

Phase 2
Trust before scale
B-2 · CI eval-gate

Required check re-runs the spec's evals in a clean container. Exit: a PR claiming GREEN locally but failing in CI cannot merge. Never parallelize workers you can't disbelieve.

Phase 3
Local fleet + board
B-1 profile L · B-4

cvg run stateless tick: tracker locks, worktrees, overlap serialization, transient/structural/ambiguous failure taxonomy. Board watches live. Exit: 5-issue diamond backlog → fleet-green unattended, one force-fail parked.

Phase 4
Platform fleet
B-1 profile C · gh aw

Bind the tick to Agent HQ / Agentic Workflows (cvg ci install); platform provides cron, settlement, sandbox. Exit: same fixture green in CI, laptop closed.

Phase 5
Verification depth
B-12 + B-13

Tier-2 judge (fresh context, different engine, fails closed) + provenance rule (sealed spec is the only instruction source) + dependency-verification eval standard. Exit: lookup-table fixture refuted; injection fixture produces zero deviation.

Phase 6
The conductor
cvg deliver

Sequence passes 1–6 + register with stops only at H1/H2; resume from derived state. Exit: brief → registered sealed backlog with exactly two human stops.

Phase 7
Sustain + receipts
B-6 + B-8

Weekly eval re-runs reopen drifted issues; cvg metrics ships cost-per-green and per-engine receipts — which then feed the router (layer 3). Exit: a manually broken invariant reopens its issue within one cycle.

12 Honest risks — the 3 a.m. list
Pass 3 is unguarded

Bad seams → coupled "atomic" tasks → the fleet churns. Only Pass 4's adversary and H2 stand in front of it. Keep H2 human until first-pass-rate receipts prove decomposition quality.

Eval authoring is the bottleneck

The loop removes humans from execution, so the human cost concentrates in writing 3+ discriminating evals. Track "refuted by tier 2" as a first-class metric; gold-sanity default-on in the fleet.

Parallel evals collide

Fixed ports and host assumptions break at 3+ workers. Ship the parallel-safety convention ($TS_WORKER_ID, task-scoped resources, worktree-per-issue) with Phase 3, not after.

Cost has no gate yet

Ten workers looping RED burn budget silently. budget_tokens beside budget_iterations; the Manager parks on either. Same discipline, price axis.

The tracker is an injection surface

The Manager reads issues — untrusted text. The sealed spec is the only instruction source; issue bodies are display text (B-13 ships with Phase 3).

Manager state-creep

The moment the tick remembers anything not derivable from board + git, restart-safety dies. Stateless tick is a hill to die on.

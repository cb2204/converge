05

Language discipline

Information is not a constraint

These words control how a system is designed. Mixing them causes accidental architecture, hidden assumptions, and gates that prove the wrong thing.

A practical classification for every statement that enters Converge.
TermPrecise meaningQuestion it answersIllustrative example
Information / factAn observed description of the current terrain. It narrows understanding but does not, by itself, command a solution.What is true now?“The operational database serves production traffic.”
ConstraintA boundary that every acceptable solution must respect. It removes options from the solution space.What must remain true, or must never happen?“Analytical workloads must not degrade production traffic.”
RequirementA falsifiable behavior or outcome the delivered system must provide.What must the system do?“Authorized users can request yesterday’s revenue by category.”
Success metricA threshold that makes a requirement measurable.How will we know it is good enough?“At least 99% of responses complete within 30 seconds.”
DecisionA chosen resolution among alternatives, with rationale and consequences.Which path did we choose, and why?“Use a read-isolated analytical path instead of querying production directly.”
AssumptionA belief used temporarily without full evidence. It must be labeled, owned, and either verified or bounded.What are we acting on before we know?“Daily query volume is estimated at 100.”
Open questionAn unresolved item with an owner and resolution path. A blocking unknown stops the descent.What still has to be learned?“Who owns verifying peak-hour load before sign-off?”
Implementation choiceA concrete technology or construction decision. It belongs after intent and terrain are understood.How will we build it?“Use change-data capture and a particular query engine.”
Good information

Descriptive and sourced

It says what was observed, where it came from, and how confident we are. Numbers are tagged as measured, estimated, or guessed.

Good constraint

Binding and testable

It states the boundary, names why it exists, and points to evidence or a gate that can detect a violation.

Good requirement

Observable and falsifiable

Another person can tell whether it is satisfied. “Fast” is vague; “p99 under 30 seconds over at least 1,000 samples” can be evaluated.

Common failure: “The client mentioned PostgreSQL” is information. Turning it into “the solution must use PostgreSQL” silently converts information into a constraint. Converge keeps that conversion visible so it can be challenged.
06

The atomic work contract

A Task-Spec tells an agent why, what, and how to prove it

A Task-Spec is a versioned Markdown file with machine-readable YAML frontmatter and six human-readable zones. It is small enough to execute, but complete enough to be challenged and verified.

YAML frontmatter · machine metadata

The scheduler-facing header

Fields such as id, status, profile, effort, depends_on, touches_paths, retry budget, execution backend, sign-off, and acceptance let scripts reason about the task without interpreting prose.

Profiles · effort-scaled depth

Lite, standard, and full

The irreducible core is always present. Standard adds explicit behavior-to-evaluation traceability. Full adds stronger operational material such as rollback and observability for higher-risk or unattended work.

Zone 1 · Intent

Why

A concise goal and context. It distills the parent product document instead of copying it.

Zone 2 · Behavior

What must happen

Given/When/Then statements with stable B-N identifiers. Each behavior must be covered by at least one evaluation on standard and full profiles.

Zone 3 · Contract

How success is proved

Runnable success criteria, the validation card, retry policy, agent contract, and one Exit Check that combines every evaluation.

Zone 4 · Guardrails

What not to do

Specific anti-patterns plus exact do-not-touch paths. This bounds blast radius and prevents “be careful” from pretending to be a control.

Zone 5 · Operations

What is still unknown

Open questions, owners, and recovery conditions. A blocking unknown becomes a blocked task, not a footnote.

Zone 6 · Recovery and signals

How to reverse and observe

Rollback steps, expected duration, metrics, alerts, and log locations. Required at full profile and useful whenever work runs unattended.

The load-bearing chain: intent → observable behavior → runnable evaluation. A behavior with no evaluation is an unproved promise. An evaluation with no declared behavior is a test with no agreed purpose.
07

Cryptographic integrity

HMAC is a tamper-evident seal, not a magic signature

HMAC means Hash-based Message Authentication Code. Converge uses HMAC with the SHA-256 hash function to detect unauthorized edits to a Task-Spec after it has passed the delegation gate.

Plain English

Think of HMAC as a seal made with a shared secret

The gate summarizes the Task-Spec into a precise payload, combines that payload with a secret repository key, and produces a short authentication code. A verifier with the same key can recompute the code. If the document changed, the codes do not match.

Canonical payloadTask ID + SHA-256 digest of the body + signed_off, signer label, and timestamp
+
Shared secret keyKnown to authorized repository or continuous-integration signers
→
HMAC-SHA256signed_off_sig: hmac-sha256-v1:…
What HMAC proves—and what it does not prove.
It doesIt does not
Detect any post-stamp edit to the covered body or sign-off values when the verifier has the key.Encrypt the Task-Spec. The content remains readable.
Show that someone or something with access to the shared repository key created the seal.Prove which individual person signed it. Anyone holding the symmetric key can create a valid HMAC.
Prevent an unkeyed editor from forging a new valid seal after changing the file.Prove that the specification expresses the right business outcome.
Bind the current Task-Spec body to its sign-off metadata at a point in time.Prove that the work has been implemented or accepted. signed_off is pre-delegation permission.
Trust Tier 1

Key + valid HMAC

The signature exists and recomputes correctly. The Task-Spec is eligible for unsupervised dispatch, subject to every other policy.

Trust Tier 2

No usable key or signature

Structural checks can still pass with a loud warning, but dispatch must be supervised. Missing crypto is not an autonomy green light.

Trust Tier 3

HMAC mismatch or malformed

The verifier hard-fails. The body or envelope changed, the key is wrong, or the signature is invalid. Do not delegate.

Critical wording rule: “Trust Tier 1/2/3” is reserved for the HMAC envelope states above. Future continuous-integration checks, independent model review, and human review should be called verification layers, not tiers, so two different systems never share the same labels.

Chain of custody

A document can be approved before the work is done

Converge uses different states for different claims. Keeping them separate prevents a valid plan from being mistaken for a completed implementation.

Draft artifactThe document can be inspected, but it does not authorize the next pass.
Canonical BRD / specThe owner has judged the artifact fit for the next stage. Pass 1’s canonical sign-off is Gate H1.
Task-Spec validatesRequired metadata, zones, behavior links, and evaluation structure are present.
signed_off: trueThe pre-delegation gate says the Task-Spec is safe to hand off. With a valid HMAC, it is Trust Tier 1.
ExecutedAn engine changes the implementation and runs the encoded evaluations within a bounded retry loop.
Evaluations greenThe implementation satisfies the checks written into the Task-Spec. This is necessary, not sufficient, for acceptance.
accepted: truePost-execution acceptance passed, including requested blast-radius and gold-sanity checks. This is the durable “done” state.
H1 · taken

Does the technical specification answer the brief?

H1 is the owner’s Pass 1 judgment. On the proving ground, the specification is signed canonical and its machine gate returns CHECK_TECH_SPEC=PASS.

H2 · future

Did the plans survive attack, and where is the trust boundary?

H2 belongs after Pass 4 Consensus. It closes all objections and chooses Fork A (whole-system trust) or Fork B (per-task trust).

Current process vs target process: the end-state conductor is designed to stop at exactly H1 and H2. Today, Track R intentionally keeps the owner involved across each pass’s five beats while the method and gates are still being validated.
Gold-sanity: an evaluation should fail on the unimplemented baseline and pass after the change. If it already passes before any work, it does not discriminate between “not built” and “built,” so it cannot honestly prove completion. The current tool can only warn when Git or the requested baseline is unavailable, so this check is strongest when a valid baseline is present.

11

Claims discipline

The honest boundaries

These are not footnotes. They define what the current evidence permits us to say.

The CLI is a referee, not an agent

It wraps deterministic scripts. External engine adapters and autonomous workers are not implemented yet.

Only Pass 0 and Pass 1 are automated

The rest of the method exists as skills and design, but not as equivalent cvg subcommands with end-to-end parity proof.

BRD and tech-spec sign-off is not HMAC

Their canonical sections and dates are gate-checked. The cryptographic envelope belongs to Task-Spec signed_off, not to every artifact in the chain.

HMAC does not identify a person

The key is symmetric and shared. It proves possession of a repository key, not non-repudiable personal authorship.

Green evaluations prove the encoded contract

If the requirements or evaluations are wrong, the implementation can be green and still miss the business outcome. Human judgment remains load-bearing at intent and trust boundaries.

Discipline-agnostic is an architectural direction

The core method is general, but some current structural gates still reflect Bash and source/transform/output patterns. Discipline-specific proof must be added without forking the universal spine.

The board is a validated spike, not a shipped command

An earlier prototype passed 9 of 9 spike evaluations and was then removed. The planned rebuild keeps snapshot mode network-free, uses a local process for live mode, derives state from files, and never becomes a second writable source of truth.

Machine-readable does not yet mean JSON everywhere

Current pass gates expose stable text tokens and exit codes. JSON and JSON Lines deepen later with derived state and continuous-integration modes.

Parity is proven on the canonical single-target path

The current capture and intent argument parsers retain the last positional path if several are supplied. The golden proof does not excuse that input-validation gap.

Some repository documentation still drifts

Known examples include skill-count wording, older Task-Spec format references, and one stale “not built” list. For current status, prefer cvg help, executable versions, accepted tasks, and cvg-todo.md.

12

Searchable reference

Every important term, in plain English

Search by acronym or idea. Definitions describe how the term is used in this report and in the current Converge repository.

Acceptance

The post-execution decision that the implementation and its evidence satisfy the Task-Spec. Successful acceptance stamps accepted: true.

ADR

Architecture Decision Record: a durable note describing context, a chosen system-level decision, alternatives, and consequences. Pass 2 produces ADRs.

Agent

An executing system that reads a contract, uses tools, changes artifacts, and emits a result. In Converge, the gate—not the agent’s confidence—decides whether work is done.

ANSI

A family of terminal control sequences used here for optional color and emphasis. The CLI removes them when output is piped so presentation never corrupts machine parsing.

Artifact

A durable output created by a pass: for example, a BRD, technical specification, ADR, plan, Task-Spec, receipt, or accepted implementation.

Assumption

A belief temporarily treated as true without complete evidence. It should be labeled, owned, and either verified or bounded before it can carry a critical decision.

Blast radius

The files, systems, data, and behavior a change can affect. Task-Specs declare expected paths so unexpected expansion can block acceptance.

BRD

Business Requirements Document: the Pass 0 artifact that captures the problem, goals, scope, success, stakeholders, risks, constraints, sources, questions, and owner sign-off.

Byte parity

Two command paths return exactly the same output bytes and exit code. It proves a wrapper did not reinterpret or decorate the gate result.

Canonical

The owner-approved artifact authorized to feed the next pass. Canonical means “current source of truth for this stage,” not “infallible or immutable forever.”

CI

Continuous Integration: automated checks run by the repository platform, usually on proposed changes. Converge’s future CI gate will rerun Task-Spec evaluations in a clean environment.

CLI

Command-Line Interface: the text command surface used by people and agents. cvg is Converge’s CLI.

Constraint

A binding boundary every acceptable solution must respect. A constraint removes options; information merely describes the terrain.

DAG

Directed Acyclic Graph: tasks connected by one-way dependency edges with no loops. It lets a scheduler know what is ready and what remains blocked.

Decision

A chosen resolution among alternatives, with rationale and consequences. A decision turns information and constraints into a committed direction.

Deterministic

Expected to return the same result for the same inputs and environment. Deterministic checks are preferred for gates because their verdicts are reproducible.

Engine

An external execution backend such as a coding-agent CLI. Converge treats engines as replaceable slots selected by flags and evidence, not as hard-coded identities.

Eval / evaluation

A runnable check that returns success or failure for an observable behavior. Together, the evaluations define the Task-Spec’s executable meaning of done.

Exit code

A number returned by a command: conventionally 0 means success, 1 means the checked contract failed, and 2 means usage or invocation error in current Converge pass gates.

Fail closed

Treat missing, malformed, or ambiguous evidence as failure rather than permission. The system stops when it cannot prove the safe path.

Fleet

The planned collection of concurrent task workers coordinated until all executable work is green or explicitly parked. No fleet runtime ships today.

Fork A / Fork B

The Pass 4 decision about the unit of trust. Fork A keeps one coupled system specification; Fork B creates many independently verifiable Task-Specs.

Frontmatter

A YAML metadata block between --- markers at the top of a Markdown file. Scripts parse it without interpreting the document’s prose.

Gap

Missing information recorded with a type and resolution path. A blocker gap prevents canonical handoff; a non-blocker remains visible without silently stopping all progress.

Gate

A decision boundary that consumes evidence and either permits the next state or stops the process. A gate is stronger than a checklist because its outcome controls flow.

Greenfield / brownfield

Greenfield starts without an existing implementation; brownfield changes a live system with inherited behavior and constraints. Both still require grounding in real terrain.

Golden diff

A comparison between automated output and an accepted manual reference. An empty diff means there was no output drift.

Gold-sanity

A Goodhart guard: evaluations must fail on the unimplemented baseline and pass on the completed change, showing they discriminate between before and after.

H1 / H2

The two named human judgment gates in the target flow. H1 approves the technical specification; H2 closes adversarial review and chooses the trust-boundary fork.

Harness

The repository-local control layer that gives agents roles, knowledge, instructions, tools, and quality checks appropriate to the real stack.

Hash / digest

A fixed-length summary of data. A plain hash detects change, but anyone can recompute it; adding a secret key through HMAC makes unkeyed forgery detectable.

HMAC

Hash-based Message Authentication Code: a keyed construction that authenticates data integrity. Converge uses HMAC-SHA256 for the Task-Spec sign-off seal.

Idempotent

Safe to run repeatedly without accumulating unintended changes. A gate or evaluation should not change its meaning merely because it ran twice.

Information

A sourced description of current reality. It can influence a decision, but it is not automatically a requirement or constraint.

JSON / JSONL

JavaScript Object Notation is structured machine-readable data. JSON Lines stores one JSON object per line, useful for append-only event and receipt streams.

KPI

Key Performance Indicator: a measurable signal tied to the outcome the owner cares about. A technical metric should trace back to a business KPI when possible.

MAC

Message Authentication Code: a value computed from data and a secret key. A matching MAC shows the covered data has not changed since a key holder authenticated it.

Manager

The planned stateless scheduler that derives ready work, dispatches workers, respects dependencies and path overlaps, and settles results. It is not implemented today.

Machine token

A stable final text line such as CHECK_BRD=PASS that an agent or script can parse without understanding the human-readable report above it.

MCP

Model Context Protocol: a standard way for AI applications to discover and call tools or retrieve context. It may be a delivery surface in a use case; it is not the Converge method itself.

Model

The inference system that generates a response. A harness or engine CLI surrounds the model with tools, context, permissions, and execution behavior; the two are not interchangeable terms.

Non-repudiation

The ability to prove a specific signer authorized something and cannot plausibly deny it. Shared-key HMAC does not provide this; per-author asymmetric signatures are needed.

p99 / 99th percentile

A threshold met by 99% of observed samples; the slowest or stalest 1% may exceed it. It needs a named sample size, window, and probe method to be meaningful.

Provenance

Where a claim came from and how trustworthy it is. Converge labels numbers as measured, estimated, or guessed and assigns verification for consequential uncertainty.

Receipt

A durable record of what ran, which evidence was observed, what it cost, and what verdict resulted. Receipts are planned inputs to later routing decisions.

Requirement

A falsifiable behavior or outcome the system must provide. It should say what success looks like without prematurely prescribing the implementation.

SHA-256

Secure Hash Algorithm with a 256-bit output. Converge uses it both for the Task-Spec body digest and inside HMAC-SHA256.

signed_off

A pre-delegation attestation that the Task-Spec’s structure and executable gate are fit to hand off. It does not mean the implementation is complete.

SLA / service-level target

A measurable service expectation such as response time, freshness, or availability. In this proving ground, the 5/30/60-minute answer classes are approved targets, not achieved results.

Symmetric key

A secret used by both signer and verifier. It is operationally simple, but every holder can create a valid HMAC, so it does not identify one person.

Task-Spec

An atomic, versioned work contract containing machine metadata, intent, behaviors, executable evaluations, guardrails, operations, and—in higher profiles—recovery and observability.

Technical specification / tech-spec

The canonical Pass 1 artifact that restates the problem, scopes the outcome, makes requirements falsifiable, records source entities and gaps, and stays above implementation technology.

touches_paths

The Task-Spec field listing files or patterns a task expects to modify. Linters and acceptance use it to expose overlaps and changes outside the declared blast radius.

Trust boundary

The point at which responsibility moves from human judgment to machine-verifiable autonomy, and the chosen size of the unit being trusted.

Trust Tier

The HMAC envelope result: Tier 1 is verified crypto, Tier 2 is structural-only and supervised, Tier 3 is mismatch or malformed and must fail.

TTY

An interactive terminal. cvg may use color on a TTY, but keeps piped output plain and parse-stable.

Validator

A structural linter that checks whether an artifact is well formed. For Task-Spec, validation alone is not the delegation gate because it does not establish the complete runtime sign-off contract.

Verification layer

A future post-execution check such as clean continuous-integration rerun, independent engine review, or risk-based human review. This term avoids collision with HMAC Trust Tiers.

Worktree

A separate Git checkout attached to the same repository. The planned worker uses one per in-flight task to isolate concurrent file changes.

YAML

A human-readable structured-data format. Task-Spec frontmatter uses YAML so scripts can parse status, dependencies, paths, budgets, and trust fields.

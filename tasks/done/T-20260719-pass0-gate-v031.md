# Close the Pass 0 gate bypasses found by the second-eyes review — check-brd.sh v0.3.1

> **Why:** The second-eyes adversarial review (2026-07-19) refuted the "100%
> closed" claim with one blocker: a BRD copied faithfully from the skill's OWN
> template — verdict still `_pending_` — passes the canonical gate, because
> `check-brd.sh` accepts the word `canonical` anywhere in the Sign-off section
> and the template's guidance sentence contains it. Three adjacent seams ride
> along: fenced example blocks satisfy checks, the open-questions check fails
> OPEN on unrecognized shapes, and exit-2 paths break the "token on the last
> line, always" agent contract. Pass 0 cannot be signed off at 100% until the
> gate survives its own template.

---

## Goal

`check-brd.sh` v0.3.0 → v0.3.1. **(a) Verdict-line anchoring:** the canonical
sign-off check matches `canonical` only on the verdict line itself, and a
verdict line carrying `pending`/`draft` never authorizes; the sign-off date
must be a VALID ISO date (month 01–12, day 01–31) on a Date/Signed line.
**(b) Fence stripping:** all checks run on the file with fenced code blocks
removed — an example inside ``` fences can neither satisfy nor trip a check.
**(c) Open questions fail closed:** question-shaped content that isn't in the
record shape (`- question:` / `owner:`) hard-FAILs canonical mode (draft:
advisory) instead of counting as "none recorded". **(d) Usage token:** every
exit-2 path (help, missing file, extra positional, unknown flag, `--draft
--no-go` conflict, PDF refusal) ends in `CHECK_BRD=USAGE_ERROR`; `cvg
capture`'s own exit-2 discovery/flag errors emit the same token, and unknown
capture flags are refused instead of being treated as a file path. The
regression suite grows to 27 rows covering every new behavior; all existing
true positives (both canonical fixtures AND the signed proving-ground BRD)
stay green byte-for-byte on the gate path. SKILL.md bumps to 0.6.0 with the
token enum updated; `bin/cvg` bumps to 0.2.1.

## Behavior

Given/When/Then scenarios the implementation must satisfy. Each scenario has a
stable `B-N` id; every eval in the Validation Card declares which behavior(s) it
`verifies:`, and the validator enforces the chain both ways (no orphan behavior,
no orphan eval).

- **B-1** — GIVEN a BRD copied faithfully from `references/brd-template.md`
  (verdict `_pending_`, the guidance sentence containing the word
  `canonical`, an ISO date elsewhere in the Sign-off section) WHEN the
  canonical gate runs THEN it exits 1, prints `CHECK_BRD=FAIL`, and never
  prints the Pass 1 handoff verdict.
- **B-2** — GIVEN a BRD whose real Sign-off is pending but which contains a
  fenced code-block EXAMPLE of a signed sign-off (heading, `canonical`
  verdict, valid date) WHEN the canonical gate runs THEN the fenced content
  satisfies nothing: exit 1, `CHECK_BRD=FAIL`, no handoff verdict.
- **B-3** — GIVEN the extended 27-row regression suite WHEN it runs THEN
  every row holds: the new negatives (template copy, fence evasion,
  open-questions shape evasion, invalid ISO date, flag conflict, unknown
  flag, two positionals, missing file, PDF token) each fail for their
  INTENDED reason; canonical fixtures in both domains AND the signed
  proving-ground BRD still pass.
- **B-4** — GIVEN any exit-2 usage path of `check-brd.sh` (missing file,
  `--draft --no-go`, unknown flag) or of `cvg capture` (zero briefs
  discovered, unknown flag) WHEN invoked THEN the output ends in the stable
  token `CHECK_BRD=USAGE_ERROR`; ShellCheck (`-x`), `/bin/bash -n` (3.2),
  and the vendored `quick_validate.py` all stay green.

## Success Criteria

Each criterion is a runnable bash function returning 0 (pass) or non-zero (fail).
Each MUST be terminal (deterministic, idempotent, non-flaky).

```bash
# eval-1: the gate survives its own template AND fenced examples (B1 + S1 closed)
eval_1() {
  F=skills/idea-to-brd/tests/fixtures/brd-template-copy.md
  G=skills/idea-to-brd/tests/fixtures/brd-codefence-evasion.md
  [ -f "$F" ] || return 1
  [ -f "$G" ] || return 1
  RC=0; out=$(bash skills/idea-to-brd/scripts/check-brd.sh "$F" 2>&1) || RC=$?
  [ "$RC" -eq 1 ] || return 1
  printf '%s\n' "$out" | grep -q 'hand off to Pass 1' && return 1
  printf '%s\n' "$out" | grep -q '^CHECK_BRD=FAIL$' || return 1
  RC=0; out=$(bash skills/idea-to-brd/scripts/check-brd.sh "$G" 2>&1) || RC=$?
  [ "$RC" -eq 1 ] || return 1
  printf '%s\n' "$out" | grep -q 'hand off to Pass 1' && return 1
  printf '%s\n' "$out" | grep -q '^CHECK_BRD=FAIL$' || return 1

  bash skills/idea-to-brd/scripts/check-brd.sh tests/uc-analytics/cvg/docs/brd-analytical-backbone.md >/dev/null 2>&1

  shellcheck -x bin/cvg bin/_ui.sh skills/idea-to-brd/scripts/check-brd.sh || return 1

  out=$(python3 skills/skill-creator/scripts/quick_validate.py skills/idea-to-brd 2>&1) || return 1
  printf '%s\n' "$out" | grep -qi 'valid'
```

## Anti-Patterns

- **Don't chase semantic perfection** — the verdict-line anchor is mechanical
  and provable; owner-voice, altitude, and per-number provenance coverage
  (S3) stay human/advisory. Mechanize only what is mechanically provable.
- **Don't decorate the gate path** — `cvg capture`'s pass-through stays an
  exact `exec`; new tokens live ONLY on cvg's own exit-2 surfaces, never on
  wrapped gate output (the R0.P byte-parity proof must survive).
- **Don't trust a new fixture that wasn't proven discriminating** — each new
  negative must demonstrably fool the v0.3.0 script before it counts as a
  regression guard (rule 8).
